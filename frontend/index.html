How this works

Normally, a language model produces exactly one token per forward pass through the (expensive) target model. Speculative decoding speeds this up by having a small, cheap draft model guess the next K tokens first. The target model then checks all K guesses in a single forward pass instead of one-at-a-time.

  • Every guessed token that matches what the target would have picked itself is accepted for free.
  • The first guess that doesn't match is rejected, and everything after it in that round is discarded.
  • The target always contributes one bonus token of its own at the end of the round — either continuing past a full acceptance, or replacing the first rejected guess.

The exact algorithm (Leviathan et al. 2023; Chen et al. 2023)

Let $p(\cdot \mid x_{<t})$ be the target model's next-token distribution and $q(\cdot \mid x_{<t})$ the draft's. The draft samples $\gamma = K$ tokens $\hat{x}_1, \dots, \hat{x}_\gamma$, one at a time, $\hat{x}_i \sim q(\cdot \mid x_{<t+i-1})$. The target then scores all $\gamma$ positions in one parallel forward pass. Each drafted token is accepted with probability

$$ \min\!\left(1,\ \frac{p(\hat{x}_i \mid x_{<t+i-1})}{q(\hat{x}_i \mid x_{<t+i-1})}\right) $$

At the first rejection, every draft token from that point on is thrown away, and a replacement is sampled not from $p$ directly but from the residual distribution

$$ p'(x) = \frac{\max(0,\ p(x) - q(x))}{\sum_{x'} \max(0,\ p(x') - q(x'))} $$

i.e. exactly the part of $p$'s probability mass that $q$ under-weighted. If instead all $\gamma$ drafts are accepted, the target's forward pass already computed $p(\cdot \mid x_{<t+\gamma})$ for free, so it contributes one more bonus token sampled from that. The load-bearing result from both papers is that this whole accept/resample procedure is exact: tokens produced this way are distributed identically to sampling from $p$ alone, no matter how bad $q$ is — a bad draft only costs you speed, never correctness.

This demo runs both models with greedy decoding ($\arg\max$), the deterministic special case of the same theorem: acceptance collapses to "did the draft's argmax match the target's argmax," and a rejection is corrected with the target's own argmax instead of a residual sample. That's why the baseline and speculative outputs you'll see below come out byte-identical — verified, not assumed.

Expected speedup

Treat the per-token acceptance probability as an i.i.d. constant $\alpha$ (a simplification both papers make for tractability — real acceptance correlates with how predictable the text is). The expected number of tokens produced per drafting round is a truncated geometric sum:

$$ \mathbb{E}[\text{tokens per round}] = \frac{1 - \alpha^{\gamma+1}}{1-\alpha} $$

Let $c$ be the ratio of one draft forward pass's cost to one target forward pass's cost (small, since the draft is much smaller). A round costs $\gamma c + 1$ target-pass-equivalents of wall-clock time, so the expected speedup over plain sequential decoding is

$$ \text{Speedup}(\alpha, \gamma, c) = \frac{1 - \alpha^{\gamma+1}}{(1-\alpha)(\gamma c + 1)} $$

The "Theory vs. measurement" panel below plugs real numbers into this formula: it uses the empirical acceptance rate $\hat\alpha$ from your actual run's rounds, and a real $\hat{c}$ measured by timing the draft model's own forward passes separately from the target's — not assumed constants — then compares the formula's prediction against the speedup that was actually clocked.

Beyond the original algorithm (2023–present)

The two 2023 papers above sample from a separate, independently trained draft model. Since then, most work has focused on getting a better $\alpha$ or a lower $c$ without paying for a whole second model:

  • Medusa (Cai et al., 2024) replaces the draft model with several extra decoding heads bolted onto the target model itself, each predicting a token further ahead; a tree of their joint top-k candidates is verified in one pass with tree attention.
  • EAGLE / EAGLE-2 (Li et al., 2024) draft at the feature level: they autoregress on the target's own penultimate-layer hidden states (which already encode a lot about what comes next) instead of raw token probabilities, and EAGLE-2 makes the draft tree's shape adapt per-step based on live confidence scores.
  • Lookahead Decoding (Fu et al., 2024) drops the draft model entirely: it generates and verifies n-gram continuations in parallel via Jacobi iteration, trading draft-model cost for extra target-side parallelism.
  • Self-speculative decoding (Zhang et al., 2023) uses the target model as its own draft by skipping a subset of its layers — no second model to load or keep in sync at all.
  • SpecInfer / tree-based verification (Miao et al., 2023) proposes and verifies a whole tree of candidate continuations per round instead of one linear chain, raising the expected accepted length per target pass.
  • Online speculative decoding (Liu et al., 2024) continuously fine-tunes the draft model on the live query stream, pushing $\hat\alpha$ up as the draft adapts to the specific traffic it's serving.

This demo deliberately implements the plain 2023 version — a separate off-the-shelf draft model, no custom heads or trees — because it's the version exposed by Transformers' assistant_model API and lets every number on this page stay a direct measurement rather than a reimplementation of someone else's kernel.
